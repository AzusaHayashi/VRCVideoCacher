# CookieBridge 内部契约（v1）

本文档是 `bridge/` 下所有子项目的共享契约。任何组件改动都必须先改这里。

## 1. 目标

浏览器扩展在任意时刻抓取 YouTube 登录 Cookie → 通过 Native Messaging 交给本地写入程序 →
加密落盘到 **vault** → 由 Native Host（以及可选的进程内插件）把最新 Cookie 交给 VRCVC
**原有的 Cookie 机制**（`%APPDATA%\VRCVideoCacher\youtube_cookies.txt`，Netscape 格式）。

## 2. 路径

| 名称 | 路径 |
| --- | --- |
| Bridge 根目录 | `%LOCALAPPDATA%\VRCVideoCacher-CookieBridge` |
| Vault（密文） | `<根>\vault.json` |
| 日志 | `<根>\logs\bridge.log`（滚动，单文件 ≤ 1 MiB × 3） |
| 状态目录 | `<根>\state\` |
| 禁用标记 | `<根>\disabled.flag` |
| 待同步标记 | `<根>\state\pending.sync` |
| Hook 状态（心跳） | `<根>\state\hook-status.json` |
| VRCVC 数据目录 | `%APPDATA%\VRCVideoCacher` |
| VRCVC Cookie 文件（**契约稳定，不要改**） | `%APPDATA%\VRCVideoCacher\youtube_cookies.txt` |

VRCVC 侧路径来自上游源码 `YTDL/YtdlManager.cs`：`Path.Join(Program.DataPath, "youtube_cookies.txt")`，
其中 `Program.DataPath = %APPDATA%\VRCVideoCacher`。这是 yt-dlp `--cookies` 的契约，跨版本稳定。

## 3. Vault 文件格式（与 VRCVC 完全解耦）

```json
{
  "formatVersion": 1,
  "createdUtc": "2026-11-01T00:30:00.000Z",
  "updatedUtc": "2026-11-01T00:30:00.000Z",
  "protection": "dpapi-current-user",
  "payloadEncoding": "base64",
  "payloadSha256": "hex(sha256(plaintext))",
  "payload": "base64(DPAPI blob of UTF-8 netscape cookie text)",
  "metadata": {
    "sourceBrowser": "chrome",
    "sourceHost": "youtube.com",
    "extensionVersion": "1.2.0",
    "cookieCount": 37,
    "loginCookiePresent": true,
    "latestExpiryUtc": "2027-05-01T00:00:00Z"
  }
}
```

* `metadata` 只放**非敏感**信息；**不得**出现 Cookie 名或值。
* `payload` 使用 Windows DPAPI（scope = CurrentUser）+ 固定 entropy
  `"VRCVideoCacher-CookieBridge/vault/v1"`。
* 读取时：先校验 `formatVersion == 1`，再校验 `payloadSha256`，再 DPAPI 解密。

## 4. Netscape Cookie 文本

与上游扩展完全一致（复用上游 `utils.mjs` 的抓取与序列化逻辑）：

```
# Netscape HTTP Cookie File
# This file is generated by VRCVideoCacher.  Do not edit.

.youtube.com	TRUE	/	TRUE	1790000000	LOGIN_INFO	xxx
...
```

规则（与 VRCVC `ApiController.FilterCookies` 保持一致）：

* 每个字段以 `\t` 分隔：domain / includeSubdomains / path / secure / expires / name / value。
* domain 强制以 `.` 开头。
* **丢弃** name 以 `ST-` 开头的行（Firefox 的 `ST-*` 会破坏 yt-dlp 的 YouTube 校验）。
* 有效性判定（同 `Program.IsCookiesValid`）：文本同时包含 `youtube.com` 与 `LOGIN_INFO`。

## 5. Native Messaging 协议

Host 名：`com.vrcvideocacher.cookiebridge`

* 传输：stdin/stdout，4 字节 little-endian 长度前缀 + UTF-8 JSON。
* 单条消息上限 1 MiB（浏览器硬限制）。

请求（扩展 → host）：

```json
{ "type": "cookie.update", "browser": "chrome", "extensionVersion": "1.2.0",
  "cookies": "# Netscape HTTP Cookie File\n...", "capturedUtc": "2026-11-01T00:30:00Z" }
```

其它 type：`ping`、`status`。

响应（host → 扩展）：

```json
{ "ok": true, "vaultUpdated": true, "cookieCount": 37, "applied": "vault+cookie-file",
  "targetWritten": true, "message": "ok" }
```

失败：`{ "ok": false, "error": "invalid-cookie-format" }`。错误字符串不得包含 Cookie 数据。

## 6. Hook 插件（进程内，可选）

> **实测结论（2026-11-01）**：Steam 版 VRCVideoCacher 是单文件自包含发布，宿主把
> `System.StartupHookProvider.IsSupported` 置为 false 且 `TRUSTED_PLATFORM_ASSEMBLIES` 为空，
> 因此 `DOTNET_STARTUP_HOOKS` 对这种二进制**不生效**。默认生效路径是 §2 的 Cookie 文件契约
> （由 Native Host 写入）。下表描述的是"宿主支持启动钩子"或"fork 构建自行 `Assembly.LoadFrom`"
> 时的进程内能力，证据见 `docs/VERIFICATION.md`。

* 载入机制（二选一）：
  1. `DOTNET_STARTUP_HOOKS`（仅框架依赖宿主 / 自编译构建，且需在管理器里显式勾选注册）；
  2. fork 构建的 `Utils/CookieBridgePlugin.TryLoad()` —— 应用自己 `Assembly.LoadFrom` 后调用
     `StartupHook.Initialize()`。
* Hook 程序集为 `CookieBridge.Hook.dll`，类 `StartupHook`（**必须在全局命名空间**），方法
  `public static void Initialize()`。命名空间写错会导致 `TypeLoadException: Could not resolve type 'StartupHook'`。
* **绝不抛异常**到 CLR：`Initialize` 整体 try/catch，失败只写日志。
* 分层能力（逐层降级）：

| 层 | 目标 | 反射成员 | 缺失时 |
| --- | --- | --- | --- |
| L1 | 写 Cookie 文件 | `YtdlManager.CookiesPath` / 否则用契约路径 | 用契约路径 |
| L2 | 串行化写入 | `YtdlCookieJar.AcquireAsync()` | 跨进程互斥量 |
| L3 | 通知 UI | `Program.NotifyCookiesUpdated()` | 静默跳过 |
| L4 | 有效性判定 | `Program.IsCookiesValid(string)` | 本地判定 |
| L5 | 版本号 | `Program.Version` / 程序集 InformationalVersion | "unknown" |

* 运行期监听 vault 文件变化（`FileSystemWatcher` + 防抖 1s），变化后重新同步，
  **不需要重启 VRCVC**。
* 心跳：每 30s 更新 `state\hook-status.json`（pid、vrcvcVersion、lastSyncUtc、layers、errors）。
* 命名管道：`VRCVideoCacherCookieBridge`（同用户），供管理器查询状态与手动触发同步。

## 7. 环境变量

| 变量 | 用途 |
| --- | --- |
| `DOTNET_STARTUP_HOOKS` | 追加 `CookieBridge.Hook.dll` 的绝对路径；**不得覆盖已有值**，用 `;` 追加与去重。**默认不注册**（Steam 单文件版无效），由管理器显式勾选 |
| `VRCCB_ROOT` | 测试/便携：重定位所有桥接数据（`vault.json`、日志、状态） |
| `VRCCB_VRCVC_DATA` | 测试：重定位 VRCVideoCacher 数据目录（只影响回退路径） |
| `VRCCB_TARGET_FILE` | 测试：重定位实际写入的 Cookie 文件（集成测试用，避免污染真实文件） |

禁用开关用 `disabled.flag`（文件），不依赖环境变量，便于随时一键禁用。
fork 构建的加载器同样先检查该文件。

## 8. 日志

格式：`2026-11-01T00:30:00.123Z [INFO ] hook        message`

* **任何日志都不得包含 Cookie 名称-值对、payload、playback cookie**。
* 允许记录：cookie 条数、是否存在 LOGIN_INFO、文件路径、字节数、耗时。

## 9. 版本兼容

* `VRCVC 版本`取自 `Program.Version`（`AssemblyInformationalVersion`，形如 `2026.10.29`）。
* 兼容矩阵：`docs/COMPATIBILITY.md`，由管理器读取并显示。
* 未知版本 → `状态: 未验证`，仍启用 L1 契约路径能力，绝不阻止 VRCVC 启动。
